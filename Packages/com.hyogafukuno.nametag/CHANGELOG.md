# Changelog

## [1.2.1] - 2026-10-07

### Fixed
- Project ウィンドウの名前タグをクリックすると、文字が薄い色になる問題を修正しました。マウスの状態に関係なく、常に通常の文字色で描画します。

## [1.2.0] - 2026-10-07

### Added
- スクリプト（`.cs`）に名前タグを付けた、または変えたときに、ファイルの 1 行目に `// Last assigned by ○○` を書き込むようにしました。既存のコメントがあれば置き換え、タグを外してもコメントは残します。
- フォルダに名前タグを付けた、または変えたときは、そのフォルダ直下のスクリプトのうち自身に名前タグがないものにも、フォルダの名前タグで書き込むようにしました（孫以降は対象外）。
- 名前タグ付きのフォルダ直下に新しく作ったスクリプトにも、フォルダの名前タグで書き込むようにしました。`.meta` ごと取り込んだスクリプトは対象外です。

## [1.1.3] - 2026-10-06

### Fixed
- Windows 環境で「Unable to load font face for [Menlo]」の警告が出る問題を修正しました。親フォルダから継承した名前タグを斜体で描画していたことが原因で、通常の書体（グレーの文字）で描画するように変更しました。

## [1.1.2] - 2026-10-06

### Changed
- リポジトリ名を `FileNametag` から `NameTag` に変更し、インストール URL と `package.json` の `repository.url` を更新しました。旧 URL も GitHub により新しい URL へ転送されます。

## [1.1.1] - 2026-10-03

### Changed
- 「存在しないアセットの割り当てを削除」を押したときに、削除対象の一覧と注意事項を表示する確認ダイアログを出すようにしました。「存在しない」は現在のブランチの状態で判定するため、未マージのアセットや GUID が一致しないアセットの割り当てを誤って消さないようにしています。
- Assignments 一覧で、存在しないアセットを記録されていたパス付きで表示するようにしました。

## [1.1.0] - 2026-10-03

### Changed
- アセットごとの割り当ての保存先を、`NameTagSettings.asset` 内のリストから `ProjectSettings/NameTags/<GUID>.txt`（1 件につき 1 ファイル）に変更しました。別々のアセットへのタグ付けが git でコンフリクトしなくなります。
- 既存の割り当ては、初回読み込み時に新しい保存先へ自動で移行します。
- 割り当てファイルに参考情報として `path` を記録し、Unity 上でアセットやフォルダを移動したときに自動で更新するようにしました。

## [1.0.2] - 2026-10-02

### Fixed
- git pull などで設定ファイルが外部から更新された場合に、エディタが古い内容で上書き保存してしまう問題を修正しました（設定ファイルの更新を検知して再読み込みします）。
- 設定変更後もインスペクタの名前タグ欄が古い表示のまま残る問題を修正しました。
- マージなどで同じアセットの割り当てが重複していると、名前タグの変更が反映されない問題を修正しました。
- 削除した直後のアセットの割り当てが「存在しない」と判定されず、一覧の表示や削除ボタンが機能しない問題を修正しました。
- Names リストの追加・削除・並べ替えが保存されない場合がある問題を修正しました。
- 複数選択で値が混在しているとき、先頭のアセットと同じ名前を選ぶと変更が反映されない場合がある問題を修正しました。
- 空白のみの名前が選択肢に表示される問題を修正しました。

## [1.0.1] - 2026-10-01

### Added
- パッケージに MIT ライセンス（LICENSE.md）を同梱しました。

## [1.0.0] - 2026-10-01

### Added
- Project Settings > NameTag Settings で名前タグに使う名前を登録できるようにしました。
- インスペクタ下部（Asset Labels の上）に名前タグを割り当てるプルダウンを追加しました。
- Project ウィンドウのアイコン右下に、白い角丸背景付きで名前タグを表示するようにしました。
- ファイル自身にタグがない場合は、最も近い親フォルダのタグを表示するようにしました（ファイル自身のタグが優先）。
